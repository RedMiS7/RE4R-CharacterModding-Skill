# RE4 Mod 诊断与修复

从精确的现有候选和缺陷开始，产出范围明确、可回退、证据可追溯的修复。可从统一入口进入，也可直接调用本 Skill。

## 开始

读取 [公共执行约束](../re4-mod-common/references/common-contracts.md)。本 Skill 共用相邻 `re4-mod-common` 的技术文档与工具；直接调用时读取这些文件即可，不再回到统一入口分流。

确认原包／父候选身份、实际部署资源、触发部位／动作／场景、已有效部分和本轮交付范围。将反馈绑定到精确候选；未知条件明确留空，不按文件时间猜测。

## 选择诊断资料

| 问题 | 按需读取 |
| --- | --- |
| 裙摆不动、穿模、不穿模但僵硬 | [部件问题库](references/component-problems.md) 的对应问题 |
| 加载失败、覆盖错误、资源配对不明 | [阶段与状态](../re4-mod-common/references/pipeline.md) 的 B、E、F 节 |
| 比例、轴向、骨架、蒙皮或模型导出异常 | [模型与骨架](../re4-mod-common/references/model-and-rig.md) 的相关节 |
| 贴图、UV、透明度、MDF 或外观异常 | [材质与纹理](../re4-mod-common/references/materials-and-textures.md) |
| 候选放行、安装、运行反馈或交付 | [验证与打包](../re4-mod-common/references/validation-and-packaging.md) |

部件库只收录已整理的裙子方法。其他缺陷依据当前资源调查，获得可复用方法后再增加对应部件和问题，不建立空白章节。

## 局部修复循环

1. **定位首次失败层。** 依次核对实际请求／部署、资源结构、坐标和绑定，再检查参数或渲染配置。建立能区分原因的最小对照。
2. **声明一个假设。** 记录允许改变的资源与字段，以及必须保留的摆动、碰撞、外形或其他已验证部分。
3. **生成独立候选。** 从指定父包构建，只改本轮变量组，不将无关阶段重新制作。
4. **回读与差分。** 完整语义差分符合允许集合，未声明修改的资源哈希一致；按实际影响执行几何、蒙皮、碰撞或材质检查。
5. **验证目标与保留项。** 打包通过后，在授权范围内核对部署与运行。改善摆动时同时检查穿模，修复穿模时同时检查自然运动。
6. **记录并选择下一步。** 未改善意味着该变量单独不足；保留独立正面证据，再依据结果选下一变量。缺少运行观察时交付离线候选和针对性测试条件。

如果证明源绑定、几何分区或目标 consumer 必须重建，将当前候选、失败证据和保留范围交给 [模型替换 Skill](../re4-model-replacement/SKILL.md) 的受影响阶段。重建后返回本流程验证原缺陷，不自动扩大为完整替换。

## 工具与交付

公共打包脚本位于 [artifact.py](../re4-mod-common/scripts/artifact.py)，用法中的 `common-dir` 指相邻的 `re4-mod-common` 目录。它不解析游戏格式或判断物理表现。

分发时将本 Skill、模型替换 Skill、公共资源目录 `re4-mod-common` 和统一入口 `re4-character-modding` 一起复制，保持四个目录同级。交付列出父候选、新候选及哈希、修改与保留范围、实际验证、尚未观察的条件和回退包。案例留在项目记录中。
