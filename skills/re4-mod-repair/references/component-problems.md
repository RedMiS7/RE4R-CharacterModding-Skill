# 角色部件问题修复 Workflow

适用于 RE4R 角色替换。按“部件 → 问题 → 定位 → 修改 → 验证”使用。

每个新模型先填写输入表，再进入对应问题。骨名、资源路径、节点数、权重、角度、碰撞尺寸和误差阈值均从当前模型确定。

## 新模型输入表

| 输入 | 填写内容 | 确认方式 |
| --- | --- | --- |
| 原始 Mod | 路径、大小、SHA-256 | 读取指定原包，不用“最新文件”猜测 |
| 游戏与工具 | 当前 build、资源格式、解析器／导出器版本 | 读取当前安装信息与工具版本 |
| 目标场景 | 角色替换槽位、服装、模式、触发动作和视角 | 用户反馈与实际资源请求；未知项留空并标注 |
| Mesh/Chain 配对 | 各目标场景实际使用的模型、骨架与物理文件 | 依赖关系、请求记录或安装资源清单 |
| 部件范围 | 裙面、内裙、附属饰物、描边所在子网格 | 子网格索引、材质索引、顶点范围与显示结果共同确认 |
| 骨骼映射 | 裙骨、挂点、骨盆、大腿、末端及父级关系 | 从当前模型层级和正权重分配生成映射 |
| 坐标约定 | 单位、轴向、矩阵布局、局部／世界变换 | 已知点变换及世界坐标回算 |
| 现有有效部分 | 已确认有效的摆动、碰撞或蒙皮 | 与精确候选绑定的观察记录 |
| 本轮交付范围 | 离线构建、安装或游戏测试 | 沿用当前任务已经明确的授权 |

生成当前模型自己的资源表和骨骼映射表。不得预设骨名、材质名相同，也不得只按可能重复的材质名合并子网格。

## 共同执行规则

1. **确认实际加载的内容。** 对照候选清单与已安装文件的路径、大小和哈希；管理器显示启用不能替代资源身份。
2. **先结构，后参数。** 先检查路径、权重、末端、重复驱动、坐标和框架，再调角度、阻尼或碰撞。
3. **每轮只改一个明确变量组。** 分开处理结构、权重、活动参数、横向连接和碰撞。需要进一步归因时，拆分变量组内的参数。
4. **保留已有效的部分。** 能摆动但穿模时保留摆动；不穿模但僵硬时保留有效的碰撞覆盖。
5. **保留可回退版本。** 从指定父包构建独立新候选，原包与已测试包保持不变。
6. **区分离线与运行结果。** 回读、蒙皮探针和静止几何测量不能代替游戏物理验证。

## 1. 裙子

### 1.1 问题：裙摆不动或摆动不足

#### 定位

按以下顺序检查，找到缺失或错误的一层后再修改：

1. **资源请求：** 当前服装是否请求了预期的 Mesh 和 Chain，是否被其他 Mod 覆盖。
2. **物理组：** 裙组是否存在，是否处于静态隔离状态，settingID 和节点数量是否匹配。
3. **骨骼路径：** 从 terminal 名称／hash 与 nodeCount 沿当前 Mesh 的父级重建路径，检查缺失节点、父级闭包和重复驱动。
4. **节点角色：** 分清固定挂点、首个模拟节点、有权重末段和 dummy 末端。普通 dummy 应无正权重；其他端点根据源模型语义判断。
5. **受限方向：** 将导出节点的受限轴转换到世界坐标，与对应的后继方向比较，记录方向误差。
6. **蒙皮响应：** 统计各子网格的裙骨、腿骨和骨盆权重；对裙骨施加受控小位移或旋转，测量裙面是否响应。
7. **活动限制：** 结构和响应正确后，再读取 angleMode、角度限制、主／次阻尼、恢复力、硬度及横向连接限制。

#### 修改

- 资源没有加载：先修正部署、冲突或路径，再评价模型物理。
- 裙组缺失：按当前骨架恢复所需分支和关联连接，保留无关分支。
- 框架错误：按当前 rest 方向重建，并重新验证；不靠加大角度补偿错误方向。
- 裙面被腿骨权重牵制：只调整已定位的裙面权重，在已有有效裙骨间重新分配，并检查归一化、量化和影响数上限。
- 活动限制过强：选择有测量依据的角度或活动参数组，做渐进式对照。每轮保留其余变量。

若怀疑腿骨权重过大，先用蒙皮探针证明响应受限，再决定本模型的权重上限。不可统一清除腿骨权重，也不可通过提高腿骨权重替代碰撞修复。

#### 验证

- 导出后仍能重建完整且无重复驱动的裙链。
- 裙面能响应目标裙骨；其他部件和非目标顶点保持预期行为。
- 游戏中相同动作下出现可见摆动和回落，同时检查是否新增穿模。
- 若骨骼方向、结构、权重和资源身份已通过，但表面仍呈折板弯曲，再检查源到目标的变形分段是否被过度合并；重建分段应另开候选。

### 1.2 问题：裙摆穿模

#### 定位

先记录穿出对象是身体、内衣还是其他裙层，以及部位、动作和视角。将静止时已有的相交与运动中才出现的相交分开。

1. **静止相交：** 比较源模型、制作场景和实际导出模型的间距、形状、层次与绑定。定位首次出现相交的阶段。
2. **碰撞归属：** 从当前骨骼映射确定骨盆、腿部及跨关节碰撞的 owner，检查端点是否随正确部位运动。
3. **覆盖缺口：** 检查裙子覆盖区域内身体／内衣的表面，以及骨盆与腿根的交界。
4. **碰撞参与：** 核对 group、node、link、collider 的过滤值及相关 header／组属性。编辑器字段名称本身不能证明游戏实际分派。
5. **变换与尺度：** 重建碰撞中心，核对单位、半径、轴向和局部偏移是否合理。

#### 测量

采用列向量约定时，碰撞点的变换为：

```text
局部点 = inverse(所属骨骼的世界矩阵) × 目标世界点
回算世界点 = 所属骨骼的世界矩阵 × 局部点
```

矩阵布局和是否需要转置由当前解析器确认。记录原点、局部点、回算点及误差，排除单位或矩阵约定错误。

等半径胶囊可用以下公式测量点间距：

```text
a、b：轴端点；r：胶囊半径；r_node：测试节点半径
t = clamp(dot(x-a, b-a) / dot(b-a, b-a), 0, 1)
clearance(x) = length(x - (a + t × (b-a))) - r - r_node
```

退化轴按球处理；变径胶囊使用对应形状算法。负值表示所采用几何解释下的重叠。报告注明是否计入节点半径，避免重复相加；表面点测试与节点测试的半径定义必须分开记录。

对当前模型同时生成三类检查：

| 检查对象 | 输出 | 用途 |
| --- | --- | --- |
| 身体／内衣 | 裙子覆盖区域内的顶点与三角形截面采样、包络外点和最大缺口 | 定位覆盖不足 |
| 裙面 | 表面间距、预计推移量和轮廓变化 | 防止碰撞体撑鼓裙子 |
| 物理节点／链段 | 节点间距、链段采样、重叠数量与最深重叠 | 判断是否存在持续接触条件 |

采样区域、密度、误差阈值和允许推移量根据当前模型尺度与外形确定。有限采样不能证明所有三角形及所有动画姿态都无相交。

#### 修改

- 静止几何或绑定已相交：只修复对应的几何、层次或绑定问题，并重新验证依赖它的骨架和 Chain。
- 碰撞覆盖不足：按当前身体拟合所需形状，补齐相关部位和关节交界，同时限制对裙面的推移。
- 碰撞跟错骨骼：修正 owner 和局部坐标，回算验证。
- 过滤或参与配置有证据表明不匹配：单独修改该配置，并检查对同文件其他分支的影响。

碰撞修复候选保留已经有效的摆动参数与权重。不得通过删除本应可见的身体表面、锁死裙摆或无限扩大碰撞体隐藏缺陷。

#### 验证

- 身体覆盖有所改善，裙面没有明显撑鼓，碰撞点世界回算通过当前模型的误差门限。
- 相同动作下穿模减少或消失，同时裙摆仍能自然运动。
- 若碰撞有效但裙摆变僵硬，进入问题 1.3，保留本轮已有效的覆盖。

### 1.3 问题：不穿模，但裙摆僵硬

#### 定位

将“没有明显穿出”和“活动不足”分别记录。不要因为活动不足而先撤销已经有效的碰撞体。

1. **节点接触：** 使用问题 1.2 的测量方法检查实际导出节点和链段，不能只检查裙面顶点。确认是否存在深重叠或大范围持续接触的几何条件。
2. **根部角度：** 读取限制模式和角度，检查根部是否限制了整个下摆移动。
3. **下游角度：** 检查裙片是否有足够弯曲余量绕过身体，而非仅整体转动。
4. **横向连接：** 检查连接的节点层级、端点配对、收缩／伸展限制，判断是否妨碍相邻裙片必要的相对移动。
5. **其他约束：** 若前述检查与对照仍不能解释问题，再检查阻尼、恢复力、硬度、权重牵制及变形分段。

#### 修改

根据证据选择一条分支，每次只执行其中一个变量组：

| 判断依据 | 本轮修改 | 本轮保持 |
| --- | --- | --- |
| 根部或下游角度范围不足 | 逐步放宽对应模拟节点的弯曲角度；根据节点角色保留挂点与末端语义 | 碰撞、权重、横向连接和其他活动参数 |
| 横向连接抵抗裙片相对移动 | 调整所定位连接的距离限制或修正配对 | 碰撞、角度、权重和其他活动参数 |
| 明显深重叠或错误碰撞归属 | 重新拟合局部接触形状或修正 owner，同时维持必要身体覆盖 | 已有效的角度与权重 |
| 其他约束有独立证据 | 单独调整相应参数、权重或分段 | 其余已验证部分 |

角度和连接限制从当前模型的空间、段长与动作需求确定，不设统一预设。字段若以弧度存储，应明确转换；连接系数也不能直接解释为实际裙面伸长比例。

若候选没有改善，记录该变量单独不足以解决问题，再选择下一分支。不要在未回读、未记录效果的情况下叠加多组修改。

#### 验证

- 同一服装和动作下摆动更明显，急停后有稳定回落。
- 已有效的碰撞覆盖仍在，身体／内衣没有新增明显穿出。
- 没有裙片拉开过大、轮廓撑鼓、翻折或持续抖动。
- 出现新缺陷时回退本轮变量，保留上一版已验证的部分。

### 1.4 裙子统一验收

#### 离线检查

- 输入包与清单一致；Mesh、Chain、骨架和碰撞引用可解析且闭包完整。
- 导出后回读；实际语义差分恰好等于本轮允许的字段集合。
- 无关部件不变；未声明修改的模型、权重和骨架保持一致。
- 重复构建结果一致；打包完整性和独立解压清单通过。
- 每个输出带有父包身份、修改范围、保留范围、测量报告和回退候选。

#### 游戏检查

通过当前管理器切换候选，核对实际部署资源，冷启动后按同一条件比较。没有运行授权时，交付候选和测试表，由实际测试者填写。

| 动作／视角 | 检查内容 |
| --- | --- |
| 站立、待机与回落 | 自然轮廓，不陷入、不撑鼓、不持续抖动 |
| 走路、跑步 | 有可见摆动，腿部与内衣不明显穿出 |
| 急转、急停 | 不锁成硬片、不翻折，停止后能回落 |
| 蹲下、起身 | 骨盆与腿根交界没有新增穿出 |
| 前、后、侧视角 | 检查各方向的间隙、轮廓与形变 |
| 当前任务要求的其他服装／模式 | 分别确认资源身份和同类动作表现 |

测试表只记录实际观察到的结果。用户验收后独立记录原话、精确候选和覆盖范围；未观察的服装、动作及场景不填写通过，也不重新打包已测试文件。

## 新模型的迭代记录模板

```yaml
component: <部件>
problem_id: <问题编号>
source_package: <原包路径和 SHA-256>
parent_candidate: <本轮父候选及 SHA-256>
resource_map: <当前模型的 Mesh/Chain/骨架配对表>
bone_map: <当前模型的挂点、模拟骨、身体骨和末端映射>
observed_symptom: <原始反馈及动作、视角；未知项注明未观察>
accepted_parts: <已经有效的部分及证据>
hypothesis: <本轮需要验证的原因>
change_scope: <允许修改的字段或资源>
preserved_scope: <必须保持的部分>
measurements: <本模型的单位、阈值、采样和间距报告>
offline_checks: <实际检查结果>
runtime_checks: <实际测试结果；未测试则注明>
evidence_level: <按已通过的阶段填写>
rollback_candidate: <回退候选>
next_action: <根据观察选择下一步>
```

## 部件分类扩展规则

当前只收录“1. 裙子”。后续有其他部件的问题需要整理时，新增顶级部件编号，在其下按具体问题编号；每个问题沿用“定位 → 修改 → 验证”的结构。尚未整理的方法不建立空白部件章节。
