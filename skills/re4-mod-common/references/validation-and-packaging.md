# 验证、打包与运行记录

## 1. 资源放行

先声明本轮输出与修改范围，再执行相应检查：

- Mesh／骨架：几何、材质索引、骨名／父级／矩阵、权重和 consumer 配对。
- MDF／纹理：字符串、shader、通道、UV、索引和依赖可达。
- Chain：路径、挂点、末端、唯一驱动、框架、碰撞坐标和所声明参数。
- PFB／RSZ／控制数据：当前 build 的 schema、实际组件与引用；资源表路径和组件字段分别验证。

回读实际产物并比较完整语义。列出允许变化的字段，确认差分恰好落在允许集合；未修改的运行资源用哈希证明一致。对结构变化与浮点量化使用各自适用的验证，不以几个文件大小或截图代替。

重复构建检查确定性，声明并处理合法浮点／导出差异。包的确定性不证明上游模型构建确定性。

## 2. 清单与 ZIP 工具

`scripts/artifact.py` 仅依赖 Python 标准库。下列 `common-dir` 始终指公共资源目录 `re4-mod-common` 的实际目录，即使当前执行的是修复或模型替换 Skill。路径由执行者解析；工作目录为当前项目。

```text
python "<common-dir>/scripts/artifact.py" inventory Work/stage --output Work/reports/stage-manifest.json
python "<common-dir>/scripts/artifact.py" verify Work/stage --manifest Work/reports/stage-manifest.json
python "<common-dir>/scripts/artifact.py" package Work/stage --manifest Work/reports/stage-manifest.json --output Output/candidate.zip
```

工具只处理纯打包树；清单和输出必须在输入树外，输出文件必须不存在。阶段清单与 ZIP 路径使用规范相对路径，拒绝大小写冲突、路径穿越和符号链接。失败产物不自动删除，应保留诊断且不晋级。

工具会精确比对文件集合、大小与哈希，按固定元数据生成无压缩 ZIP，并回读全部成员验证。它不解析游戏格式，不检查运行依赖，不证明 Mod 可用，也不代替安装管理器。无压缩用于稳定、可比较的输出；若另选压缩方案，应锁定工具并重新验证。

确认打包树仅包含计划运行文件及必要管理器元数据，路径根符合实际管理器合同。另行解压到新的短项目目录，对照清单；记录最终 ZIP 大小、SHA-256、清单和原始父候选。管理器配置／包内版本标签也应与新候选相符。

阶段目录的 `verify` 是精确整树比较，不能用于有其他资源的整个游戏目录。安装后应编写或使用对照清单的只读子集审计，保留无关 Mod。

## 3. 安装与回退

沿用当前会话权限，通过当前管理器执行受控切换，并记录冲突与优先级。Fluffy 管理的部署由 Fluffy 维护，不用外部复制绕过管理器的同路径冲突。

安装前后保存候选资源清单，核对实际部署字节。不要清空整个 natives、删除未知资源或覆盖其他 Mod。回退使用保留的已测试包，并通过管理器恢复；说明回退包仍可能包含其已知缺陷。

离线构建本身不要求退出未参与当前操作的程序。实际安装／运行按用户授权和当前管理器需要协调状态；不因为缺少运行授权而停止可以独立完成的离线工作。

## 4. 运行与证据等级

切换候选后冷启动，并记录实际执行条件：角色、服装／模式、入口、动作、视角、相关光照／状态、资源身份和观察。针对修复目标选最小足够测试矩阵；没有做的测试留作未观察。

| 等级 | 可以说明的内容 |
| --- | --- |
| reference-inferred | 来自参考或源语义的待验证结构与方法 |
| offline-accepted | 指定候选通过了其声明范围的离线检查 |
| runtime-load-pass | 精确候选在实际记录的场景加载通过 |
| runtime-rejected | 精确候选出现阻断缺陷，仍保留独立通过的观察 |
| runtime-confirmed | 对精确候选和实际覆盖范围有用户或运行证据的明确验收 |

简短用户验收紧接唯一明确交付时，可以绑定该交付的有限接受范围。独立写入运行报告，记录绑定方式和包哈希；不能补造未报告的服装、动作、冷启动或长时间测试。不要改写构建时的离线报告或重打已验收包。

## 5. 当前项目交付记录

记录候选 ID、父包哈希、当前 build、输入／工具锁、修改和保留范围、完整清单、离线报告、运行原话、未知项、包路径／大小／哈希、部署状态、回退及下一步。

状态续接示意：

```text
当前阶段与候选：依据现有报告填写
已有效部分：列出证据和适用范围
当前缺陷：保留用户原话与触发条件
本轮假设：说明一个可区分的原因
允许变化：资源与字段
必须保持：其他已验证部分
结果：实际通过、失败或未观察
下一步：根据当前结果选择可执行动作
```

实际配置、资产路径和工具发现结果保存在项目内。Skill 只维护通用方法。
