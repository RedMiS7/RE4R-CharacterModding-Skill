# 阶段与项目状态

## 使用范围

适用于完整角色替换、资源定位和多轮修复。按当前任务选择阶段，已经有可靠证据通过的内容可以续接。局部问题不要强制重建整个人物。

## A. 输入与工作目录

记录原包／源模型、目标角色和服装／模式、当前游戏 build、交付范围、已获授权与已知问题。为输入、工具和输出记录大小与 SHA-256。参考资产的使用与分发范围沿用用户已提供的信息。

建议在当前项目分开保存：

```text
Ref/                  原始模型、参考和提取源的只读副本
Scripts/              当前模型的构建与审计脚本
Work/reports/         结构、几何、回读、差分和工具日志
Work/candidates/      各轮候选及其身份记录
Work/stage/           准备打包的纯运行资源树
Output/               通过所声明离线检查的新包
reports/runtime/      独立运行观察与验收
PROJECT_STATE.md      当前进度、已有效部分、未决项和下一步
source-lock.json      输入与工具的身份
```

可以适配已有项目结构。恢复工作先确定最新未被后续记录取代的候选，不按文件时间猜测“最新版”。

## B. 当前 build 与资源配对

1. 读取当前安装信息和有效官方归档顺序，确认提取工具能处理目标压缩／加密格式。
2. 从当前依赖、资源请求及准确路径探针解析实际使用的文件，记录提取来源和优先级。
3. 将缺失路径保留为缺失证据，不凭参考包合成别名。
4. 建立每条输出路径的资源配对表：

| 字段 | 内容 |
| --- | --- |
| 场景 | 服装、模式、过场、模型展示或当前任务要求的其他场景 |
| consumer | 实际请求该资源的对象／组件与证据 |
| 运行路径 | 完整相对路径及当前格式后缀 |
| 角色 | 身体、面部、头发、物理、辅助或共享资源 |
| 配对 | Mesh、MDF、贴图、Chain、骨架与相关控制文件 |
| 计划 | 替换、保留、经证明的别名、局部修补或明确排除 |
| 输出来源 | 将提供该资源的当前项目产物 |

按 consumer 分区源模型。不要把完整身体复制到每个辅助槽位，也不要把模型展示加载成功扩展为所有游戏场景成功。共享骨架和其他共享路径要单独评估影响范围。

## C. 源模型与工具检查

盘点保留对象、材质槽、UV 层及顺序、顶点颜色、法线、透明度、绑定、父级、骨矩阵和形态键保存值。多种源表示可能分别保留不同语义，应记录采用哪一种作为外形／材质／物理依据。

显式区分用户想保留的造型状态、面部表情、动画和诊断形态键。需要烘焙时记录对象、键、值与位移；不要将所有形态键清零或全部烘焙。删衣、短裙等变体按用户指定对象／面片范围处理，不依据模糊名称批量删除。

用当前目标的已知有效资源做工具身份检查：导入、无意图修改的导出、重新读取并比较几何／材质／UV／骨骼／权重或 Chain 语义。记录确切工具版本和配置。

## D. 构建与分阶段验证

| 阶段 | 输出 | 进入下一阶段的依据 |
| --- | --- | --- |
| 几何／骨架 | 比例策略、源到目标变换、骨映射、分区模型 | 坐标与绑定一致，代表姿态没有明显异常 |
| 材质／纹理 | 材质索引表、着色器与贴图映射、UV 语义 | 实际导出引用闭包、UV 与通道对应 |
| 面部准备 | 实际面部 consumer、骨映射、动作探针 | 静态外形和动作检查分开记录 |
| 物理 | 路径、挂点、框架、权重、碰撞与参数 | 结构通过，活动与碰撞分别验证 |
| 导出 | 每个运行 consumer 的最终资源 | 回读字段和资源差分符合计划 |
| 打包 | 清单、新包、大小和哈希 | 确定性、回读与独立解压通过 |
| 运行 | 安装资源身份、动作／场景观察 | 用户要求的范围有实际证据 |

模型与面部准备读 [模型与骨架](model-and-rig.md)；材质读 [材质与纹理](materials-and-textures.md)；部件缺陷读 [部件问题库](../../re4-mod-repair/references/component-problems.md)。

## E. 加载失败的分流

先确定失败的精确候选、consumer、入口和最后正常的对照。检查部署文件和覆盖优先级，再检查二进制与依赖。

- 模型未替换：确认实际部署文件、资源请求与目标槽位。
- 加载停滞：检查实际读取路径、无法解析的记录、失效字符串和缺失依赖。
- 特定服装／过场失败：增加该场景的 consumer 证据，不直接沿用其他场景结论。
- 导出工具报错：保留日志与产物，不能只看外层命令是否返回成功。

隔离候选按资源职责拆分，但同时闭合它所引用的依赖。例如 MDF 对照必须使用存在且匹配的贴图引用。保持被隔离变量之外的资源一致，不通过连续修改物理掩盖材质／依赖失败。

Blender 后台脚本应将 Python 异常映射为失败退出，可使用 `--python-exit-code 1`，同时检查日志和目标文件。Windows 长路径问题优先使用较短的项目工作目录，不删除原输入或改写游戏目录来规避。

## F. 状态与下一轮

状态至少记录：当前阶段、精确候选及父包、已通过部分、用户原话、阻断问题、报告位置、未知项和下一步可执行动作。

候选被拒绝时保留独立正面观察，明确是哪一个充分性假设被否定。不要因一个缺陷把已有效的全部内容回退，也不要把某次成功归因于同轮修改的单个参数。

游戏或工具更新后，重新验证受影响的路径、schema、偏移和格式合同；不能仅根据后缀未变宣称兼容。
