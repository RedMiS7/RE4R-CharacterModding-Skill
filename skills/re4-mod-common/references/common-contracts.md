# 公共执行约束

修复和模型替换流程共用本文件。先读当前项目的 AGENTS.md、PROJECT_STATE.md 和最新有效报告，确定目标角色／服装、源模型或原包、当前 build、交付范围与已有授权。缺失关键输入时只询问影响正确性的内容，同时继续独立审计。

若当前工作目录存在 `config.json`，读取其中工具、插件和游戏路径作为定位输入；没有时兼容读取 `re4-mod.config.json`，两者不合并。该文件由 `npx . init` 生成，也可人工填写；继续核实文件、版本和当前阶段的工具合同，不将保存路径视为兼容性或运行通过的证据。

## 事实与修改范围

- 当前 build 和实际请求决定运行路径、格式、consumer 与别名；源模型决定外形、材质、保存形态与绑定语义。
- 先建立当前资源配对表和骨骼映射。参考 Mod 用于结构比较，其骨名、偏移、节点数量、权重、角度、半径与矩阵变换需按当前输入重新推导。
- 保持源文件、已测试候选和验收包不变，输出新候选。先验证结构、框架和绑定，再调整参数；每个修复候选只改变一个明确变量组。
- 保留独立通过的部分，回读实际导出文件并验证未声明变化的资源与语义。制作场景正常不代表游戏资源正常。
- 当前项目中保存候选与父包身份、输入／工具锁、修改与保留范围、报告、反馈、未知项和下一步。案例和实际参数留在项目中。

## 工具与证据

按当前阶段发现 Blender、源格式导入器、RE Mesh/Chain/MDF 工具、build 提取能力和 Python；只检查本轮需要的工具。用匹配的有效资源完成导入／导出／回读，确认工具合同。

本组 Skill 不包含游戏资产、模型或格式转换器。工具缺失时说明受影响阶段，继续独立工作，不生成伪造游戏二进制或承诺未验证格式可用。

沿用当前会话授权；调用 Skill 不额外授权安装、控制管理器或启动游戏，已有授权无需重复请求。参考推断、离线通过、加载通过和运行验收分开记录，未知条件保持未观察。

交付时说明具体改动、离线检查、实际运行结果、包路径与哈希以及回退方式。公共工具见 [验证与打包](validation-and-packaging.md)；其中的脚本目录始终属于 `re4-mod-common`。

## 维护范围

只加入可移植的方法和经过验证的通用工具。部件问题按“部件 → 问题 → 定位 → 修改 → 验证”扩展，不写历史模型、旧候选编号、固定角色参数、项目专用路径或案例过程。没有可靠方法时先做当前项目调查。

`re4-mod-common` 只存放两个执行 Skill 共用的文档与工具，不作为可调用 Skill。若缺少所需公共文件，报告具体缺口并继续可以独立完成的工作。
