# 材质、纹理与资源引用

## 1. 建立材质合同

为当前 Mesh 的每个子网格记录材质索引、MDF 对应项、shader/MMTR、贴图类型与路径，以及实际使用的 UV 流。同名材质可跨不同子网格，不能仅按名称覆盖记录。

优先从当前 consumer 的有效材质中选择符合表面用途的模板。皮肤、头发、布料、金属和眼睛的 shader 语义不同；能装入贴图不代表渲染正确。

保留材质索引相关的当前组件查询合同。隐藏部件可能仍有材质／资源查询需求；任何保留占位 Mesh 或兼容材质的方案都需要当前依赖证据，不自动把全部原生材质带入新模型。

## 2. 源外观与 UV

记录源材质的贴图、颜色／发光因子、透明度、节点连接、UV 名称与位置顺序。未绑定材质和未绑定贴图分别处理。

将源表面用途追溯到实际导出的 UV 位置流。活动层或 UV 名称相同不足以证明导出采样正确；按 loop/corner 检查数值，注意 UV 接缝复制的顶点。

通道含义从源文档、当前 shader 和实际像素检查确认；记录颜色空间、法线方向、alpha／mask 与纹理编码。不要按纹理名称后缀猜测所有通道。

## 3. 构建与序列化

按当前格式编码纹理，解码输出做通道与尺寸检查。MDF 的记录顺序、名称、字符串、shader 路径与纹理引用都需要回读。

复制材质记录时区分可复用语义与源文件的序列化偏移、缓冲信息和缓存。由当前 writer 正确重算相关字段；若工具需要特定适配，先确认 schema 与字段原值，并通过可回读的最小对照验证。不能把旧记录的偏移直接当新文件偏移，也不能无差别清零未知字段。

有完整纹理和字符串的基线可帮助区分数据损坏与外观配置错误。所有 runtime 纹理引用应解析到当前包、已证明的原生资源或明确依赖。

## 4. 按现象检查

| 现象 | 先检查 | 对照方向 |
| --- | --- | --- |
| 部分材质加载停滞 | MDF 回读、字符串与偏移、实际贴图路径及格式 | 修复最小损坏资源，保留几何与物理 |
| 白色／异常发光 | 源绑定、颜色／发光因子、shader、通道 | 定位表面与引用，不先盲调亮度 |
| 图案采错或不连续 | 源 UV 意图、导出 UV 流、材质采样 | 按面角验证实际 UV |
| 半透明变硬洞 | alpha 数据、测试／混合模式、shader 与排序 | 分开检查裁切和透明混合 |
| 衣物看似穿出 | 实际几何间距、深度／透明排序 | 区分透明渲染与真实物理相交 |

## 5. 验证

读回 MDF 和纹理，验证与 Mesh 索引配对、全部依赖和通道；再在任务要求的视角、光照与服装下观察。加载通过不等于透明度、皮肤、发光或法线效果已通过。

用局部修改范围解释差分，保留其他材质。当前任务没有要求的渲染状态不自动扩大为全场景验证。
